# Training Log — журнал тренера и клиента

Сайт: https://savcov89-hub.github.io/Claude-cod/ (GitHub Pages).
Работает на Supabase: база Postgres, вход через Google или по ссылке из письма, сервер — Edge Function `api`.
Тест без входа: `?demo=1` (та же логика в браузере, пример данных).

## Что нового в v3
- **Зал.** Вкладки клиентов, отмеченных «Пришёл». Переключение в одно касание, журнал не закрывается.
  На вкладке: подходы x/y и время с последнего подхода (жёлтая рамка — ждёт больше 3 минут).
  Журнал сразу открывает следующую по плану тренировку, день можно сменить.
- **Быстрый ввод.** Вес подставлен по подсказке прогрессии, в поле повторов — цель.
  ✓ отмечает подход «как в плане»; цифры можно поправить. RIR необязателен. «+ подход / − подход».
- **Меню упражнения «⋯».** Заменить — только сегодня или в программе насовсем (исходное — первым в списке, вернуть
  можно всегда; замену на сегодня можно оставить в программе), «Подходы и повторы» (любой диапазон, сохраняется
  в программе), пропустить сегодня, удалить (у каждого упражнения;
  последнее в тренировке — только когда есть другое).
- **Порядок упражнений.** Стрелки ↑↓ прямо на карточке меняют порядок этой тренировки; тренер может сразу
  «Сохранить в программе». Изменённое в программе число подходов сразу видно в открытом журнале.
- **Комментарий к упражнению.** Строка внизу карточки: попадает в историю, в следующий раз виден «в прошлый раз: …».
- **Время на тренировке.** В журнале и на вкладке клиента — сколько прошло с отметки «Пришёл», не обнуляется.
- **«+ Упражнение».** Добавить упражнение в тренировку на сегодня: подходы, диапазон повторов и RIR в один экран.
  Попадает в историю, прогрессия у каждого упражнения своя. Добавленное тренером и выполненное хотя бы одним подходом
  при завершении встаёт в программу (на своё место, с этими подходами и повторами); у клиента — только на сегодня.
  Из меню — «Добавить в программу» сразу или «Убрать из тренировки».
- **Свободная тренировка.** В зале вместо программы (или когда программы ещё нет): пустой журнал, упражнения набираются
  по ходу. В истории — «Свободная тренировка», очередь дней программы не сдвигается. В следующий раз — «Как в прошлый раз»
  (те же упражнения, подходы и повторы, вес по прошлым результатам). «Сохранить как тренировку программы» добавляет её
  днём в программу клиента или создаёт новую — так программа собирается из реальных тренировок.
- **Забытый «Ушёл».** Час без новых подходов — тренировка записывается сама (временем последнего подхода)
  и клиент уходит из зала; отмеченный без единого подхода уходит через 2 часа. Перед записью журнал берёт с сервера
  всё, что внесено на другом телефоне или в карточке клиента; если там записывали меньше часа назад — ждёт дальше.
  Если «Ушёл» не смог записать тренировку с подходами, клиент остаётся в зале с подсказкой проверить журнал.
- **Незавершённая тренировка не теряется.** Если в зале у клиента есть начатая тренировка (в том числе свободная,
  например после перезапуска приложения), вкладка открывает именно её. В карточке клиента — плашка «Не завершена:
  … Открыть» для начатых и не завершённых за 14 дней. Если в открытой вкладке нет подходов, а на сервере есть начатая
  тренировка с подходами, ни «Ушёл», ни автоотметка «2 часа без подходов» не отпускают клиента без неё: вкладка
  переключается на неё (автоматически — и записывает, если час без подходов); «Завершить» спустя час после последнего подхода ставит время
  этого подхода. «Сохранить как тренировку программы» в свободной тренировке только добавляет день в программу —
  саму тренировку записывает «Завершить» (или «Ушёл»).
- **Программу поменяли во время тренировки.** Сделанные подходы не пропадают: то же упражнение получает свои подходы,
  убранное из программы остаётся в этой тренировке как добавленное (в программу не возвращается).
- **Подсказки прогрессии (двойная прогрессия).** Вес прибавляется, если во всех подходах дошли до верха диапазона
  или хотя бы в одном рабочем подходе сделали больше верха; иначе тот же вес и +1 повтор. Шаг: +1 кг до 10 кг,
  дальше +2,5 кг; на стековых тренажёрах, блоках и кроссовере вес в плитках, шаг +1 плитка. Если шаг больше 20 % веса
  (1→2 плитки, гантели 10→12,5), сначала добирают верх диапазона +2 повтора. Сильно перерос вес или сменился диапазон —
  прибавка по оценке максимума (до +20 %). Недобор 1–2 повтора (например, сразу после прибавки) — вес остаётся;
  недобор 3+ повтора в большинстве подходов → −8 % (или больше по оценке, до −20 %); блок не ниже 1 плитки, свой вес —
  «облегчите вариант». Записанный запас повторов (RIR) учитывается. Для гравитрона — наоборот.
  Проверка: `npx tsx scripts/simulate-month.ts отчёт.md` — месяц 30 клиентов через ту же логику.
  У своего упражнения тренер выбирает, на чём оно выполняется (блок / кроссовер, блочный тренажёр, рычажный на блинах,
  штанга / гантели, свой вес) — от этого зависят плитки или кг. Свои упражнения можно изменить в «Базе».
- **Не та тренировка.** «сменить» под названием тренировки в журнале: если подходы уже отмечены — «Перенести подходы»
  (те же упражнения получают свои подходы, остальные сделанные добавляются только на этот раз) или «Начать с нуля».
  Записанную по ошибке тренировку тренер удаляет в истории (корзина): она пропадает из истории и статистики,
  подсказки веса берутся из предыдущей, очередь дней программы откатывается.
- **История.** По тренировкам или «По мышцам»: грудь, спина, дельты, руки, квадрицепс, бицепс бедра, ягодицы,
  икры, пресс — у каждого упражнения его результаты по датам.
- **Замеры.** Утром — вес за сегодня, шаги и калории за вчера (средние за 7 дней, графики); обхваты шеи/талии/бёдер,
  процент жира по формуле ВМС США, индекс безжировой массы (FFMI, с поправкой на рост 1,8 м), калорийность (Кэтч — Макардл по сухой массе или Миффлин — Сан Жеор) и белок.
  Расход с шагами: обмен × 1,2 + ходьба (0,5 ккал на кг на 1000 шагов сверх 3000) + тренировки (≈4 ккал на кг за занятие);
  без шагов — множитель по числу тренировок.
  Расход по факту: средние калории за 2 недели минус изменение веса (≈7700 ккал на кг) — нужны хотя бы 4 дня с калориями
  и 3 взвешивания в каждой неделе.
  Вносит тренер в карточке клиента или сам клиент.
- **Вход.** Google, почта + пароль или код из письма. Тренер может сам создать клиенту вход по паролю в карточке
  клиента — без писем, клиент сразу подключён; пароль меняется значком ключа. Если почта клиента уже занята пустым
  аккаунтом (например, роль выбрана по ошибке), владелец приложения задаёт ему пароль так же; аккаунт с данными не трогается.
  «Забыли пароль?» присылает ссылку для нового пароля. Встроенная почта Supabase отправляет
  лишь несколько писем в час — для писем с кодом нужен свой SMTP.
- **Сводка.** В зале, посещения за 7 дней, новые результаты, «Требуют внимания»
  (новый результат, снижение, застой 3+ тренировки, не был 7+ дней, нет программы), рекорды недели,
  посещаемость за 30 дней.
- **Без интернета.** Приложение хранится в телефоне и открывается без сети с последними загруженными данными.
  Подходы, завершение тренировки, «Пришёл/Ушёл» и замеры без сети копятся на телефоне и отправляются по порядку,
  когда сеть появится (вверху — полоса «Нет сети» и сколько ждёт отправки). Первый вход — только с интернетом.
- **Тема.** Светлая или тёмная — как на телефоне; кнопка вверху (солнце / луна) закрепляет светлую или тёмную на этом
  устройстве. Клиент видит в своём кабинете аватарку, которую выбрал тренер.
- **Карточка клиента.** Имя меняется карандашом рядом с ним; нажатие на аватарку — выбор одной из 35 готовых картинок
  (пират, лысые и с залысинами с тёмной, светлой и рыжей бородой, женщины с длинными и короткими волосами, в очках и др.) или буквы. Заметки (цель, ограничения — видны прямо в зале), сетка посещений 8 недель,
  прогресс, история, программы, код подключения, архив.
- **Вживую.** Открытый журнал раз в 4 секунды подтягивает записи с другого телефона: тренер вводит вес и повторы —
  клиент видит их у себя («Тренер записывает · обновлено только что»), и наоборот. Подтягивает, только когда на этом
  телефоне нет несохранённых правок и не набирается число; ответ, пришедший позже своего сохранения (медленная сеть),
  отбрасывается, чтобы не стереть только что отмеченный подход. На главной клиента — «Тренировка идёт» с кнопкой «Открыть».
- **Картинки упражнений.** У каждого из 97 упражнений базы — фигура в начальной и конечной точке со своим снарядом
  (штанга, гантели, блок, стек, рычаг с блинами, скамья, тренажёр), работающие мышцы выделены цветом
  (`src/ui/exerciseArt.tsx`: позы задаются положением таза, кистей и стоп, локти и колени находятся сами).
  В журнале — маленькая картинка с номером упражнения; нажатие открывает «как выполнять»: движение по кругу,
  «Начало» и «Конец», положение тела и мышцы. Картинки есть в выборе упражнения и в «Базе» (раскрыть — движение,
  начало и конец). Своим упражнениям тренера подбирается картинка их группы мышц. Тёмная тема поддерживается.
- **Графики рисуются.** На «Замерах» и в «Прогрессе» график при появлении прорисовывается слева направо, заливка
  проявляется следом, последняя точка появляется в конце; графики на странице стартуют друг за другом.
  При включённом в телефоне «уменьшении движения» — без анимации.
- **Плавность журнала.** Готовое упражнение ещё мгновение остаётся открытым (видна последняя ✓), затем сворачивается,
  а карточки ниже плавно подъезжают; так же — при перестановке и раскрытии. Когда приходят записи с другого телефона,
  экран не сдвигается (и на iPhone, где у Safari нет своего «якоря прокрутки»). Цифра в поле появляется сразу,
  журнал пересчитывается следом. Двойное касание ✓ отмечает подход один раз. На узких экранах (до 389 px)
  подсказка веса уходит под название, карточка не шире экрана. Поиск при замене упражнения находит и в других группах мышц.
- **Вдвоём в одной тренировке.** Тренер и клиент могут отмечать подходы одновременно, каждый со своего телефона:
  сохранение несёт версию, с которой телефон начал, и сервер сливает правки двух телефонов по подходам
  (`src/draftMerge.ts`) вместо отказа «изменено на другом устройстве». Подход, изменённый на обоих, — сделанный
  важнее несделанного, иначе побеждает последний сохранивший. Запись в базу условная (одна операция проверяет версию
  и пишет), поэтому сохранения в одну и ту же миллисекунду не затирают друг друга. Если один уже нажал «Завершить»,
  а у другого остались неотправленные подходы (или он завершил без сети), они дописываются в ту же запись
  (до 12 часов после завершения) — тренировка не задваивается; у второго журнал показывает «Тренер завершил тренировку».
- **Личные рекорды.** После «Завершить» — праздник с новыми рекордами (лучший подход по расчётному максимуму против всех
  прошлых тренировок: «60 кг × 12, было 42,5 × 12, +35 %»), у тренера в зале и у клиента. В «Прогрессе» — список
  лучших результатов по каждому упражнению с датой и ростом с начала.
- **Прогресс.** По каждому упражнению: график расчётного 1ПМ, лучший подход, % за период,
  статус (рекорд / рост / без изменений / застой / снижение). Подходы на мышцу за 7 дней.
- **Клиенты без приложения.** Тренер добавляет клиента сразу; код подключения можно выдать позже,
  история сохраняется.
- **Программы.** Изменить, копировать программу (этому или другому клиенту), архив. Отдельную тренировку —
  «Копировать тренировку» в раскрытом дне: в любую программу любого клиента или в новую. Упражнения можно менять местами.
  Лимит 9 подходов на мышцу за тренировку — теперь предупреждение, а не запрет; косвенное участие = 0,5 подхода.
  Показан объём за цикл (ориентир 10–20).
- **Программа текстом.** «Скопировать текстом» под программой (или у одной тренировки) кладёт в буфер текст для
  мессенджера: по строке на упражнение — «Жим ногами 45 кг 3х15», вес и повторы из подсказки на следующую тренировку;
  без прошлых результатов — диапазон «3х10–15».
- **Быстрые повторы.** В редакторе программы под каждым упражнением — 4–6 · 6–8 · 8–12 · 12–15 · 15–20 (одно нажатие),
  над тренировками — те же кнопки «для всей программы» (с подтверждением; подходы и RIR не меняются).
- **Тренировка на…** В редакторе программы у каждой тренировки — выбор мышц: ягодицы, ноги, грудь · спина, грудь ·
  трицепс, спина · бицепс, плечи · руки, руки, верх, низ, всё тело и др. Тренировка заполняется подходящими упражнениями
  (ещё нажатие — другие упражнения на те же мышцы), название подставляется; всё можно поправить.
- **Шаблоны.** Всё тело 3× и 2×, Верх/низ 4×, Верх/низ + ТТН 5×, ТТН×2 6×, Акцент на ягодицы 4×,
  прежние классические сплиты и разовые тренировки.
- **База.** +20 упражнений (бабочка, Смит, брусья, гравитрон, Т-гриф, маятниковый присед, сведение бёдер,
  кроссовер-махи, байесовские сгибания, face pull, икры сидя и др.). Для своих упражнений — выбор мышц.

## Структура
- `backend/app.ts` — вся серверная логика (`createHandler(sdk)`): маршруты, права доступа, расчёты.
- `backend/server.ts` — запуск этой логики на Supabase: HTTP-обработчик, проверка токена, хранение строк в Postgres.
- `backend/router.ts` — маршрутизатор, общий для сервера и тестового режима.
- `supabase/functions/api/` — Edge Function; `server.js` собирается из `backend/` командой `npm run build:api`.
- `supabase/migrations/` — схема базы: одна таблица `kv_rows`, прямой доступ из браузера закрыт.
- `src/supabase.ts` — вход и запросы к серверу; `src/local/*` — тестовый режим в браузере.
- `src/ui/*` — интерфейс; `src/analytics.ts` — прогресс, застой, подсказки; `src/templates.ts` — шаблоны.

## Команды
- `npm run check` — проверка типов.
- `npm run build:api` — собрать серверную функцию.
- `npm run build:demo` — тестовая версия одним файлом (`artifact/training-log.html`).
- `npm run dev` — интерфейс локально; адрес и ключ Supabase берутся из `.env.local` (образец — `.env.example`).
- `npm run build` — сайт в `dist/` (на GitHub Pages собирается автоматически).

## Публикация
- **Сайт.** Каждый пуш в `main` собирает сайт (Actions → Deploy site) и кладёт сборку в ветку `gh-pages`,
  которую показывает GitHub Pages. Адрес Supabase и публичный ключ — в `.env.production`.
- **Сервер.** Проект Supabase `mtheahciwliosrzadhbd` («Training Log»). Функцию `api` выкладывает Actions → Deploy Supabase,
  если в GitHub добавлен секрет `SUPABASE_ACCESS_TOKEN` (Settings → Secrets and variables → Actions → Secrets).
  Без секрета функцию можно выложить вручную: `SUPABASE_ACCESS_TOKEN=... npx supabase functions deploy api
  --project-ref mtheahciwliosrzadhbd --no-verify-jwt --use-api` (после `npm run build:api`).
- **Схема базы.** Миграции из `supabase/migrations/` применяются вручную (SQL Editor в Supabase или через API).
  В проекте остались таблицы и функция `training-api` от ранней версии — приложение их не использует.
- **Вход.** Site URL и Redirect URLs в Supabase уже указывают на адрес сайта.

## Вход через Google (один раз)
1. console.cloud.google.com → создайте проект → APIs & Services → **OAuth consent screen**:
   тип External, название приложения, ваша почта. Затем опубликуйте приложение (Publish app).
2. APIs & Services → Credentials → Create credentials → **OAuth client ID** → Web application:
   - Authorized JavaScript origins: `https://savcov89-hub.github.io`
   - Authorized redirect URIs: `https://mtheahciwliosrzadhbd.supabase.co/auth/v1/callback`
3. Скопируйте Client ID и Client secret → Supabase → Authentication → Sign In / Providers → **Google** →
   включите, вставьте оба значения, Save.

## Письма со ссылкой для входа
Встроенная почта Supabase доставляет только участникам проекта и с жёстким лимитом. Клиентам проще входить
через Google. Если нужен вход по почте для всех — подключите свой SMTP (Authentication → SMTP Settings), например Resend.

## Резервные копии
По вторникам, четвергам и субботам (~04:17 МСК) Actions → **Backup data** выгружает всю таблицу `kv_rows`, шифрует её
паролем из секрета `BACKUP_PASSWORD` и кладёт в ветку `backups` (последние 36 копий — около трёх месяцев). Тот же запуск обращается к серверу,
чтобы бесплатный проект Supabase не уснул после недели без использования. Запустить вручную: Actions → Backup data →
Run workflow. Нужны секреты `SUPABASE_ACCESS_TOKEN` (уже есть) и `BACKUP_PASSWORD` (пароль хранить отдельно — без него
копию не открыть).

Восстановление:
1. Скачать файл из ветки `backups` и расшифровать:
   `openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in 2026-10-04.json.gz.enc -out rows.json.gz && gunzip rows.json.gz`
2. `npx tsx scripts/restore-backup.ts rows.json > restore.sql` и выполнить `restore.sql` в Supabase → SQL Editor.
   Строки из копии возвращаются как были (те же id, данные и порядок), добавленные позже не трогаются.

## Проверки сохранения
- `npx tsx scripts/check-merge.ts` — слияние правок двух телефонов на 20 000 случайных парах правок.
- `npx tsx scripts/check-saving.ts` — все способы сохранить тренировку через серверную логику: два телефона,
  одновременные сохранения, завершение при неотправленных подходах, повторная отправка, офлайн, смена программы,
  свободная тренировка, следующая неделя, удаление записи.
- `ANON=… SRK=… node scripts/check-two-phones.mjs` — два настоящих браузера (тренер и клиент) на локальном Supabase
  записывают одну тренировку одновременно; порядок запуска — в начале файла.
- `node scripts/check-ui.mjs` (при запущенном `npm run dev` или `APP=…?demo=1` для собранной версии) — телефон 390×844
  с процессором в 4 раза медленнее: все способы записать тренировку с экранов (зал, «Ушёл», карточка клиента,
  замена, добавленное упражнение, пропуск, порядок, «сменить» с переносом, свободная тренировка после перезапуска,
  удаление, кабинет клиента, автозавершение, двойное касание ✓, вес с запятой, перезагрузка сразу после отметки)
  и плавность: не сдвигается ли строка и экран, не теряется ли фокус при вводе, как быстро отвечает касание,
  удерживается ли экран, когда приходят записи с другого телефона (и без «якоря прокрутки», как в Safari),
  нет ли прокрутки вбок на экранах 320, 360 и 375 px.

## Локальная проверка сервера
`npx supabase start` (нужен Docker) поднимает базу, вход, почту (http://127.0.0.1:54324) и функцию.
`SRK=<service_role key из npx supabase status> npx tsx scripts/supabase-parity.ts` прогоняет пример данных
через Postgres и сверяет ответы API с тестовым режимом. После `npm run build:api` перезапустите контейнер
`supabase_edge_runtime_training-log`, чтобы функция подхватила новую сборку.
