# Training Log — журнал тренера и клиента

Сайт: https://savcov89-hub.github.io/Claude-cod/ (GitHub Pages).
Работает на Supabase: база Postgres, вход через Google или по ссылке из письма, сервер — Edge Function `api`.
Тест без входа: `?demo=1` (та же логика в браузере, пример данных).

## Что нового в v3
- **Зал.** Вкладки клиентов, отмеченных «Пришёл». Переключение в одно касание, журнал не закрывается.
  На вкладке: подходы x/y и время с последнего подхода (жёлтая рамка — ждёт больше 3 минут).
  Журнал сразу открывает следующую по плану тренировку, день можно сменить.
- **Быстрый ввод.** Вес подставлен по подсказке прогрессии, в поле повторов — цель.
  ✓ отмечает подход «как в плане»; цифры можно поправить. RIR необязателен. «+ подход / − подход».
- **Меню упражнения «⋯».** Заменить на сегодня (исходное — первым в списке, вернуть можно всегда),
  пропустить сегодня, изменить порядок (только сегодня или в программе), убрать из программы (тренер).
- **«+ Упражнение».** Добавить упражнение в тренировку на сегодня: подходы, диапазон повторов и RIR в один экран.
  Попадает в историю, прогрессия у каждого упражнения своя. Из меню — «Добавить в программу» или «Убрать из тренировки».
- **Свободная тренировка.** В зале вместо программы (или когда программы ещё нет): пустой журнал, упражнения набираются
  по ходу. В истории — «Свободная тренировка», очередь дней программы не сдвигается. В следующий раз — «Как в прошлый раз»
  (те же упражнения, подходы и повторы, вес по прошлым результатам). «Сохранить как тренировку программы» добавляет её
  днём в программу клиента или создаёт новую — так программа собирается из реальных тренировок.
- **Забытый «Ушёл».** Час без новых подходов — тренировка записывается сама (временем последнего подхода)
  и клиент уходит из зала; отмеченный без единого подхода уходит через 2 часа.
- **Подсказки прогрессии (двойная прогрессия).** Вес прибавляется, если во всех подходах дошли до верха диапазона
  или хотя бы в одном рабочем подходе сделали больше верха; иначе тот же вес и +1 повтор. Шаг: +1 кг до 10 кг,
  дальше +2,5 кг; на стековых тренажёрах, блоках и кроссовере вес в плитках, шаг +1 плитка. Если шаг больше 20 % веса
  (1→2 плитки, гантели 10→12,5), сначала добирают верх диапазона +2 повтора. Сильно перерос вес или сменился диапазон —
  прибавка по оценке максимума (до +20 %). Недобор 1–2 повтора (например, сразу после прибавки) — вес остаётся;
  недобор 3+ повтора в большинстве подходов → −8 % (или больше по оценке, до −20 %); блок не ниже 1 плитки, свой вес —
  «облегчите вариант». Записанный запас повторов (RIR) учитывается. Для гравитрона — наоборот.
  Проверка: `npx tsx scripts/simulate-month.ts отчёт.md` — месяц 30 клиентов через ту же логику.
  У своего упражнения тренер выбирает, на чём оно выполняется (блок / кроссовер, блочный тренажёр, рычажный на блинах,
  штанга / гантели, свой вес) — от этого зависят плитки или кг. Свои упражнения можно изменить в «Базе».
- **История.** По тренировкам или «По мышцам»: грудь, спина, дельты, руки, квадрицепс, бицепс бедра, ягодицы,
  икры, пресс — у каждого упражнения его результаты по датам.
- **Замеры.** Утром — вес за сегодня, шаги и калории за вчера (средние за 7 дней, графики); обхваты шеи/талии/бёдер,
  процент жира по формуле ВМС США, индекс безжировой массы (FFMI, с поправкой на рост 1,8 м), калорийность (Кэтч — Макардл по сухой массе или Миффлин — Сан Жеор) и белок.
  Расход с шагами: обмен × 1,2 + ходьба (0,5 ккал на кг на 1000 шагов сверх 3000) + тренировки (≈4 ккал на кг за занятие);
  без шагов — множитель по числу тренировок.
  Расход по факту: средние калории за 2 недели минус изменение веса (≈7700 ккал на кг) — нужны хотя бы 4 дня с калориями
  и 3 взвешивания в каждой неделе.
  Вносит тренер в карточке клиента или сам клиент.
- **Вход.** Google, почта + пароль или код из письма. Тренер может сам создать клиенту вход по паролю в карточке
  клиента — без писем, клиент сразу подключён; пароль меняется значком ключа. Если почта клиента уже занята пустым
  аккаунтом (например, роль выбрана по ошибке), владелец приложения задаёт ему пароль так же; аккаунт с данными не трогается.
  «Забыли пароль?» присылает ссылку для нового пароля. Встроенная почта Supabase отправляет
  лишь несколько писем в час — для писем с кодом нужен свой SMTP.
- **Сводка.** В зале, посещения за 7 дней, новые результаты, «Требуют внимания»
  (новый результат, снижение, застой 3+ тренировки, не был 7+ дней, нет программы), рекорды недели,
  посещаемость за 30 дней.
- **Карточка клиента.** Заметки (цель, ограничения — видны прямо в зале), сетка посещений 8 недель,
  прогресс, история, программы, код подключения, архив.
- **Прогресс.** По каждому упражнению: график расчётного 1ПМ, лучший подход, % за период,
  статус (рекорд / рост / без изменений / застой / снижение). Подходы на мышцу за 7 дней.
- **Клиенты без приложения.** Тренер добавляет клиента сразу; код подключения можно выдать позже,
  история сохраняется.
- **Программы.** Изменить, копировать другому клиенту, архив. Упражнения можно менять местами.
  Лимит 9 подходов на мышцу за тренировку — теперь предупреждение, а не запрет; косвенное участие = 0,5 подхода.
  Показан объём за цикл (ориентир 10–20).
- **Шаблоны.** Всё тело 3× и 2×, Верх/низ 4×, Верх/низ + ТТН 5×, ТТН×2 6×, Акцент на ягодицы 4×,
  прежние классические сплиты и разовые тренировки.
- **База.** +20 упражнений (бабочка, Смит, брусья, гравитрон, Т-гриф, маятниковый присед, сведение бёдер,
  кроссовер-махи, байесовские сгибания, face pull, икры сидя и др.). Для своих упражнений — выбор мышц.

## Структура
- `backend/app.ts` — вся серверная логика (`createHandler(sdk)`): маршруты, права доступа, расчёты.
- `backend/server.ts` — запуск этой логики на Supabase: HTTP-обработчик, проверка токена, хранение строк в Postgres.
- `backend/router.ts` — маршрутизатор, общий для сервера и тестового режима.
- `supabase/functions/api/` — Edge Function; `server.js` собирается из `backend/` командой `npm run build:api`.
- `supabase/migrations/` — схема базы: одна таблица `kv_rows`, прямой доступ из браузера закрыт.
- `src/supabase.ts` — вход и запросы к серверу; `src/local/*` — тестовый режим в браузере.
- `src/ui/*` — интерфейс; `src/analytics.ts` — прогресс, застой, подсказки; `src/templates.ts` — шаблоны.

## Команды
- `npm run check` — проверка типов.
- `npm run build:api` — собрать серверную функцию.
- `npm run build:demo` — тестовая версия одним файлом (`artifact/training-log.html`).
- `npm run dev` — интерфейс локально; адрес и ключ Supabase берутся из `.env.local` (образец — `.env.example`).
- `npm run build` — сайт в `dist/` (на GitHub Pages собирается автоматически).

## Публикация
- **Сайт.** Каждый пуш в `main` собирает сайт (Actions → Deploy site) и кладёт сборку в ветку `gh-pages`,
  которую показывает GitHub Pages. Адрес Supabase и публичный ключ — в `.env.production`.
- **Сервер.** Проект Supabase `mtheahciwliosrzadhbd` («Training Log»). Функцию `api` выкладывает Actions → Deploy Supabase,
  если в GitHub добавлен секрет `SUPABASE_ACCESS_TOKEN` (Settings → Secrets and variables → Actions → Secrets).
  Без секрета функцию можно выложить вручную: `SUPABASE_ACCESS_TOKEN=... npx supabase functions deploy api
  --project-ref mtheahciwliosrzadhbd --no-verify-jwt --use-api` (после `npm run build:api`).
- **Схема базы.** Миграции из `supabase/migrations/` применяются вручную (SQL Editor в Supabase или через API).
  В проекте остались таблицы и функция `training-api` от ранней версии — приложение их не использует.
- **Вход.** Site URL и Redirect URLs в Supabase уже указывают на адрес сайта.

## Вход через Google (один раз)
1. console.cloud.google.com → создайте проект → APIs & Services → **OAuth consent screen**:
   тип External, название приложения, ваша почта. Затем опубликуйте приложение (Publish app).
2. APIs & Services → Credentials → Create credentials → **OAuth client ID** → Web application:
   - Authorized JavaScript origins: `https://savcov89-hub.github.io`
   - Authorized redirect URIs: `https://mtheahciwliosrzadhbd.supabase.co/auth/v1/callback`
3. Скопируйте Client ID и Client secret → Supabase → Authentication → Sign In / Providers → **Google** →
   включите, вставьте оба значения, Save.

## Письма со ссылкой для входа
Встроенная почта Supabase доставляет только участникам проекта и с жёстким лимитом. Клиентам проще входить
через Google. Если нужен вход по почте для всех — подключите свой SMTP (Authentication → SMTP Settings), например Resend.

## Локальная проверка сервера
`npx supabase start` (нужен Docker) поднимает базу, вход, почту (http://127.0.0.1:54324) и функцию.
`SRK=<service_role key из npx supabase status> npx tsx scripts/supabase-parity.ts` прогоняет пример данных
через Postgres и сверяет ответы API с тестовым режимом. После `npm run build:api` перезапустите контейнер
`supabase_edge_runtime_training-log`, чтобы функция подхватила новую сборку.
