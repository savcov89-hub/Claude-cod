# План: генератор рационов питания (Новосибирск, РФ)

Статус: MVP реализован (см. README.md). Сделаны этапы 1–3 и часть 4: данные (150 продуктов, цены по трём уровням,
нормы с источниками), ядро (энергия, нормы, ЛП‑солвер, раскладка по дням), опросник с беременностью, лактацией,
диабетом 1/2, ХБП по стадиям и непереносимостями, страницы меню / покупок / норм / источников, тесты.
Открытые вопросы раздела 7 остаются в силе для фазы 2.

## 1. Что строим

Веб‑приложение, которое по профилю человека (пол, возраст, рост, вес, активность, цель)
и выбранному бюджету (эконом / бизнес / премиум) собирает рацион на день или неделю:

- каждый день разбит на приёмы пищи с граммовками;
- суммарно за день выполнены нормы по калориям, белкам/жирам/углеводам, клетчатке,
  витаминам и минералам (ВОЗ + российские МР 2.3.1.0253‑21);
- используются продукты, реально доступные в Новосибирске, с ценами по трём уровням;
- на выходе список покупок с итоговой стоимостью и экспорт (печать / PDF / ссылка).

## 2. Данные

### 2.1 Состав продуктов (нутриенты)

| Источник | Что даёт | Лицензия | Роль |
|---|---|---|---|
| USDA FoodData Central (SR Legacy + Foundation Foods) | ~150 нутриентов на 100 г, в т.ч. все витамины и минералы | Public domain | Базовая таблица: гречка, кефир, творог, курица, свёкла и т.д. есть почти все |
| Скурихин, Тутельян «Химический состав российских пищевых продуктов» | Российская номенклатура: сметана 15%, творог 5%, хлеб «Бородинский», сосиски и т.п. | Неясная, бумажная книга | Сверка и дополнение для специфически российских продуктов, вводим вручную |
| Open Food Facts | Штрихкоды, бренды, российские упаковки | ODbL | Опционально, на фазе 2: конкретные бренды из «Ярче!», «Марии‑Ра», «Ленты» |

Решение: один внутренний JSON/SQLite со 150–250 продуктами и ~35 нутриентами.
Каждая запись хранит ссылку на источник (USDA id или «Скурихин, стр.»), чтобы данные
были проверяемы. ETL‑скрипт на Python строит таблицу из сырых файлов USDA.

### 2.2 Региональный ассортимент

Три слоя продуктов:

- База РФ: крупы (гречка, овсянка, перловка, рис), картофель, капуста (свежая и квашеная),
  морковь, свёкла, лук, яйца, курица, свинина, говядина, минтай, сельдь, молочка
  (кефир, творог, сметана, сыр), хлеб, растительное и сливочное масло, бобовые.
- Сибирь: кедровые орехи, облепиха, брусника, клюква, черника, папоротник, грибы,
  речная и северная рыба (пелядь, муксун, омуль, щука, судак), мёд, льняное масло.
- Премиум/импорт: лосось, форель, авокадо, миндаль, киноа, ягоды зимой, индейка,
  сыры выдержанные, оливковое масло.

Сезонность: флаг «сезон» на овощи, фрукты, ягоды, чтобы зимой алгоритм не предлагал
свежую клубнику в экономе.

### 2.3 Цены по Новосибирску

| Уровень | Откуда цены | Ассортимент |
|---|---|---|
| Эконом | Росстат / ЕМИСС: средние потребительские цены по Новосибирской области (ежемесячно, официально) + СТМ сетей | Базовый набор, субпродукты, сезонные овощи, замороженная рыба |
| Бизнес | Полки «Ярче!», «Мария‑Ра», «Лента», «Ашан» (ручная таблица с датой) | + индейка, красная рыба, орехи, ягоды, зелень круглый год |
| Премиум | «ВкусВилл», фермерские рынки, Центральный рынок | + фермерские, органик, деликатесная рыба, импортные фрукты |

Решение для MVP: ручная таблица цен `prices.json` с полями `product_id, tier, price_per_kg,
source, date`. Парсинг сайтов сетей не делаем: хрупко и юридически серо. На фазе 2:
админ‑страница для обновления цен и импорт Росстата скриптом.

### 2.4 Нормы

- Макро и энергия: ВОЗ/FAO. Жиры <30% энергии, насыщенные <10%, транс <1%,
  свободные сахара <10% (цель <5%), соль <5 г/сут, овощи и фрукты ≥400 г/сут,
  клетчатка ≥25 г/сут, белок по МР (0,8–1,2 г/кг для обычных, выше для спортсменов).
- Микронутриенты: МР 2.3.1.0253‑21 Роспотребнадзора как основной источник
  (железо, кальций, магний, цинк, йод, селен, витамины A, D, E, C, B1, B2, B6, B9, B12,
  PP, K). ВОЗ/FAO 2004 для сверки. Для каждого нутриента хранить min и верхний
  допустимый уровень (UL), иначе алгоритм «перекормит» витамином A печенью.
- Энергия: формула Миффлина‑Сан Жеора + коэффициент активности + цель
  (дефицит 15–20%, поддержание, профицит 10%).

Нормы задаются таблицей по полу и возрастным группам, не хардкодом.

## 3. Алгоритм

Классическая «задача о диете» через линейное программирование, но в два шага,
чтобы результат был съедобным, а не «2 кг печени и 400 г отрубей».

1. Недельная корзина (LP). Переменные: граммы каждого продукта за неделю.
   Цель: минимизировать стоимость (или отклонение от бюджета для бизнес/премиум).
   Ограничения: нутриенты в диапазонах [min, UL] × 7 дней; лимит на продукт
   (например, печень ≤150 г/нед, яйца ≤10 шт/нед); минимальное разнообразие
   (не менее N овощей, не менее 2 источников белка); овощи+фрукты ≥2800 г/нед;
   исключения пользователя.
2. Раскладка по дням и приёмам пищи. Библиотека блюд‑шаблонов (каша + молоко + ягоды,
   суп, гарнир + белок + овощи, творог + фрукт). Жадный алгоритм с проверкой, что
   каждый день укладывается в ±10% по калориям и макро, а неделя в сумме закрывает
   микронутриенты (так разрешено по МР и ВОЗ: нормы оцениваются в среднем за неделю).

Солвер: `highs-js` (WASM, работает в браузере) или `glpk.js`. Для 250 продуктов × 40
ограничений решение занимает миллисекунды, сервер не нужен.

Если пользователю важны именно рецепты с названиями, переходим на вариант «LP по блюдам»:
переменные не продукты, а порции блюд из библиотеки 100–150 рецептов. Это даёт
более «человеческий» рацион, но требует подготовить рецептурник.

## 4. Технологический стек

Рекомендация: один SPA без бэкенда для MVP.

- Vite + React + TypeScript, Tailwind CSS, shadcn/ui для компонентов.
- Данные в JSON, собираются скриптами (Python, `data/etl/`).
- LP‑солвер в браузере (`highs-js`).
- Хранение профиля и сохранённых рационов: localStorage, затем Supabase, если нужны аккаунты.
- Деплой: Vercel / Cloudflare Pages, бесплатно, HTTPS, работает с телефона.
- Экспорт: печатная версия через CSS `@media print`, PDF из неё, ссылка с параметрами.

Альтернатива, если нужен бэкенд сразу (личные кабинеты тренера, клиенты, оплата):
Next.js + Postgres (Supabase) + тот же солвер на сервере.

## 5. Дизайн

- Один сценарий на главной: профиль → бюджет → ограничения → «Собрать рацион».
- Результат: неделя вкладками по дням, карточки приёмов пищи, под ними панель
  «нормы»: кольца/полоски по каждому нутриенту с цветом (норма, недобор, превышение).
- Список покупок, сгруппированный по отделам магазина, с ценой строки и итогом за неделю,
  переключатель «эконом / бизнес / премиум» прямо на этом экране для сравнения.
- Светлая и тёмная тема, шрифт с хорошей кириллицей (Inter / Manrope),
  мобильная вёрстка в приоритете.
- Тон: спокойный, «аптечно‑чистый», без стоковых фото еды; иконки продуктов.

## 7. Вопросы для решения

1. Аудитория: приложение для себя, для клиентов тренера, или публичный сервис?
   От этого зависят аккаунты, брендинг и серьёзность дисклеймера.
2. Платформа: веб с телефона достаточно, или нужен Telegram‑бот / мобильное приложение?
3. Персонализация: какие параметры обязательны? Пол, возраст, рост, вес, активность,
   цель. Нужны ли исключения (вегетарианство, без лактозы, без глютена, халяль, пост)?
4. Формат результата: только продукты с граммовками, или блюда с названиями и
   рецептами? Второе заметно дороже по подготовке данных.
5. Горизонт: день, неделя или обе опции? Рекомендую неделю: микронутриенты честно
   закрываются только в среднем за неделю.
6. Бюджет: только три уровня или ещё поле «рублей в день»? Как часто готовы обновлять
   цены вручную? Раз в месяц достаточно для MVP.
7. Нормы: устраивает связка «ВОЗ по макро + МР 2.3.1.0253‑21 по микро»?
   У ВОЗ нет полной таблицы РСП по всем витаминам, российские нормы здесь полнее.
8. Данные: допустимо ли использовать USDA как основу состава продуктов?
   Это единственная полная и свободная таблица. Российские таблицы дополняем вручную.
9. Экспорт: печать, PDF, ссылка, отправка в Telegram?
10. Дисклеймер и медицинские ограничения: беременность, диабет, ХБП исключаем
    из целевой аудитории на старте или поддерживаем отдельные режимы?

## 8. Рекомендации

- Начать с MVP без бэкенда: быстрее, бесплатно в хостинге, легко показать клиентам.
- Нормы и цены хранить как данные с источником и датой, а не в коде. Это главный
  актив приложения, он должен быть проверяем.
- Обязательно верхние пределы (UL) по микронутриентам и лимиты по продуктам,
  иначе LP выдаст математически верный, но несъедобный рацион.
- Оценивать нормы за неделю, а не за каждый день: так рекомендуют и ВОЗ, и МР,
  и это даёт разнообразие.
- Сразу заложить флаги сезонности и региона, даже если в MVP регион один.
- Дисклеймер: приложение не заменяет врача; при заболеваниях консультация обязательна.
