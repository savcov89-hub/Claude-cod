# Training Log

Журнал тренера и клиента: React + Vite, сервер и данные на Supabase, сайт на GitHub Pages
(https://savcov89-hub.github.io/Claude-cod/). Подробности и настройка — в README.md.

## Договорённости с владельцем
- Общение и тексты интерфейса — на русском.
- Готовые проверенные изменения отправлять сразу в `main`, без pull request:
  коммит в рабочую ветку сессии, затем `git push origin HEAD:main`. После отправки проверить запуски в GitHub Actions.
- Каждое изменение записывать в `CHANGELOG.md` (новое сверху, по-русски, для владельца) в том же коммите.
  Там же раздел «Нужно переделать» — что владелец просил переделать позже.
- Пуш в `main` публикует сайт (Deploy site → ветка `gh-pages`) и, при изменениях серверной части, функцию `api`
  (Deploy Supabase; работает, только если в GitHub есть секрет `SUPABASE_ACCESS_TOKEN`).
- Проект Supabase: `mtheahciwliosrzadhbd`. Новые миграции в продакшен применять вручную (через API или SQL Editor).
  Старые таблицы и функцию `training-api` в проекте не трогать без согласия владельца.

## Проверка перед отправкой
- `npm run check` — типы; `npm run build` — сайт; `npm run build:api` — серверная функция.
- Интерфейс смотреть в браузере: `npm run dev`, без Supabase — с `?demo=1` (пример данных, переключатель Тренер/Клиент).
- Изменения в `backend/`: локальный Supabase (`npx supabase start`, нужен Docker) и `scripts/supabase-parity.ts`.
- Изменения сохранения тренировок: `npx tsx scripts/check-merge.ts`, `npx tsx scripts/check-saving.ts`
  и два браузера на локальном Supabase — `scripts/check-two-phones.mjs`.
- Изменения интерфейса журнала и зала: `node scripts/check-ui.mjs` (сценарии записи с экранов и плавность).
- Изменения подсчёта объёма и программы по объёму (`src/volume.ts`, `src/volumePlanner.ts`, мышцы упражнений):
  `npx tsx scripts/check-volume.ts`.
- Изменения слияния программы с правками из зала (`src/programMerge.ts`): `npx tsx scripts/check-merge.ts`.
- «Рацион» (`ration/`): `npm run test:ration` (нормы на 7 профилях) и check-ui сценарии 39 (карточка клиента у тренера)
  и 40 (у клиентов скрыт; с `RATION_FOR_CLIENTS = true` — тренер назначает, клиент видит).
- Картинки упражнений (`src/ui/figure/`): `npx tsx scripts/check-figures.tsx лист.html фото/` — суставы, опора, равновесие,
  и посмотреть лист глазами рядом с фото из `scripts/figure-refs.json`.
- Изменения прогрессии или журнала: `npx tsx scripts/simulate-month.ts отчёт.md` — 30 клиентов, месяц Пн/Ср/Пт;
  сравнить «в диапазоне / легко / тяжело» и число колебаний с прошлым прогоном.
  После `npm run build:api` перезапускать контейнер `supabase_edge_runtime_training-log`.

## Устройство
- `backend/app.ts` — вся логика и права доступа; работает и на сервере (`backend/server.ts`), и в демо (`src/local/`).
- Данные — таблица `kv_rows` (колонка `json`, не `jsonb`: порядок ключей важен для интерфейса).
  Доступ к ней только у серверной функции; браузер ходит в `/functions/v1/api`.
- Живая тренировка: после сохранения журнал шлёт сигнал «сохранено, ревизия …» через Supabase Realtime
  (канал `w:<программа>:<день>`, без данных), второй телефон сразу читает черновик; в демо — BroadcastChannel.
  Проверка раз в 4 с — запасная.
- Объём недели (`src/volume.ts`): каждое упражнение базы расписано по частям мышц — 1 основная работа, ½ участие;
  двусуставные и односуставные части считаются отдельно, группа — по самой нагруженной части. План — программы клиента
  за неделю (`perWeek` программы, иначе каждая тренировка раз в неделю).
- Программа по объёму (`src/volumePlanner.ts`): цели программы `targets` (подходы в неделю на часть мышц) → дни по схеме,
  жадный подбор упражнений по недостающему объёму, затем подгонка подходов 2–5, замены и удаления. Цели — из опыта
  и акцентов программы (`focus`, `targetsFor`): акцент ×1,4 объёма роста, остальное ×0,5; упражнения акцентов первыми.
- Ограничения клиента (`src/restrictions.ts`, `notes.restrictions` клиента): неподходящие упражнения не подбираются
  («По объёму», шаблоны, «Обновить упражнения», «Тренировка на…» — `adaptExercises`) и уходят в конец списков с пометкой.
- План акцентов клиента (`src/phases.ts`, `phases` клиента): этапы {акценты, подходов в неделю, недель} с даты начала;
  прогресс — подходы акцентов из истории за даты этапа; «По объёму» берёт цели этапа (`stageTargets`).
- Замена «насовсем» из журнала (`POST /api/programs/:id/days/:dayId/exercise`, `everywhere`): во всех днях программы
  с этим упражнением, открытые черновики перестраиваются (`takeSwap`), замена пишется в `swapLog` программы и в `swaps`
  клиента (`src/restrictions.ts` `withSwap`). Подбор («По объёму», шаблоны, «Обновить упражнения» — `adaptExercises`,
  `planByVolume({ swaps })`) ставит выбранное вместо заменённого. Редактор, открытый раньше, сливается по `swapLog`
  (`mergeProgramDays(base, mine, theirs, log)`).
- Замеры (`src/body.ts`): `rangeSeries` — график за период (до месяца по дням, дальше по неделям пн–вс), `weeksBack` —
  последние 4 недели; в интерфейсе — check-ui сценарий 38.
- «Рацион» (`ration/`, из репозитория Diet): отдельная страница `dist/ration/` в рамке вкладки «Рацион»
  (`src/ui/Ration.tsx`). У клиентов вкладка пока скрыта по просьбе владельца (`RATION_FOR_CLIENTS = false`: нет вкладки
  у клиента и кнопки «Назначить клиенту», `assign=1` не передаётся) — работает только в карточке клиента у тренера.
  Данные из «Замеров» после `#` (`embed=1&key&sex&age&h&w&act&strength&theme`), ответы и последний рацион —
  в localStorage по `key`. Стили — Tailwind 4 только там (`ration/vite.config.ts`), service worker её не трогает.
  Цены примерные, без привязки к городу — так и писать в текстах.
  Тренер — та же страница в карточке клиента (`role=trainer&name`), данные из «Замеров» клиента; у дневника своё меню
  внизу — разделы рациона строкой сверху (`menu=top`, класс `.app.menu-top`). «Назначить клиенту»:
  рамка шлёт `postMessage` `tl-ration:assign` → `POST /api/client/:id/ration` (таблица `ration:<ключ клиента>`, одна строка
  `{plan, assignedAt, trainerName}`). Рамка по готовности (`tl-ration:ready`) и при каждом открытии вкладки получает
  `tl-ration:assigned` из `GET /api/ration`; у клиента новое назначение (`assignedAt` ≠ `seen` в localStorage) заменяет
  показанный рацион, свой пересобранный — нет (`ration/src/ui/host.ts`, `storage.ts` `PlanInfo`).
- Брошенная тренировка (есть подходы, 3 ч без сохранений) записывается сервером сама датой последнего сохранения,
  когда её черновик читают по пути: приложение клиента, карточка, «Зал», открытие тренировки (`finishStale`).
